# 03 元数据与组织

> 写作参考（本地），不会渲染到站点。

## front matter

每个文档文件开头的 `---` 之间是元数据（YAML 格式），最常用的字段：

```markdown
---
sidebar_position: 1        # 在侧边栏中的排序（数字越小越靠前）
title: 接口限流             # 页面标题（不写则取一级标题）
description: 限流规则说明   # 页面描述，用于 SEO 和搜索结果
---
```

- `title` 省略时自动取正文第一个 `#` 标题
- `description` 建议写上，会让搜索结果更友好

## 目录与侧边栏

- 所有文档放在 `docs/` 下，目录即文档分类
- 侧边栏在 `sidebars.ts` 中手动维护，新增文档后需要把文档 id 加进对应分类
- 文档 id = 相对 `docs/` 的路径（不含扩展名），如 `docs/api/user-auth.md` 的 id 是 `api/user-auth`

## 多语言写作要点

- `docs/` 下写简体中文；英文翻译放 `i18n/en/docusaurus-plugin-content-docs/current/` 对应路径
- **文件名、目录结构必须与 `docs/` 完全一致**，否则翻译不生效
- 英文版缺翻译时自动回退中文，不会报错
- 标题建议写显式锚点，保证翻译后链接不断：

```markdown
### 常见问题 {#faq}
```

详细流程见站点内文档 [多语言管理](../docs/maintenance/i18n-guide)。

## 多版本写作要点

- `docs/` 始终是**最新内容**；发布版本 = 运行 `npm run docusaurus docs:version <版本号>` 拍快照
- 快照生成后，历史版本内容改 `versioned_docs/version-<版本号>/` 下的文件
- 站内链接请用**相对路径**，避免跨版本跳转错误

详细流程见站点内文档 [多版本管理](../docs/maintenance/version-guide)。
